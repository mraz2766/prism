# Prism 产品体验与响应逻辑审查（2026-08-14）

## 审查范围

本次审查覆盖已安装的 Prism 1.6.0（7）：Dashboard 概览、出口历史、通用设置、菜单栏设置、网络设置，以及实时出口检测、GeoIP 回退、状态发布和历史写入的实现路径。Popover 因 macOS 状态项未被当前截图工具暴露，未取得本轮可接受截图，仅结合代码检查，不作为完整视觉证据。

用户核心目标是：菜单栏安静、准确地展示当前互联网出口；VPN 或节点变化后尽快给出反馈；大陆直连可用；稳定运行时不产生明显 CPU、电量和网络负担。

## 主要发现

### P0：出口候选与最终刷新不是同一个事务

`RealtimeExitMonitor` 先通过探针得到一个地址，然后调用 `NetworkLookupService.refresh()`；后者又重新查询一次 IPv4/IPv6。两次查询可能走不同规则或遇到不同瞬时失败，导致“探针看到上海、刷新却得到东京”，或相反。这是典型的检查与使用之间不一致，也是当前抖动的根因。

改进：引入 `ExitSnapshot`，一次检测产出地址、来源、路由类型、时间和可复用的本次 IPIP 位置载荷。后续 GeoIP、状态更新与历史写入必须消费同一快照，禁止第二次重新决定出口。

### P0：瞬时失败被当成真实切换

当前海外探针失败后立即采用国内 IPIP；没有候选状态、连续确认、最短驻留或 Provider 熔断。真实历史在 55 秒内出现 6 次 JP/CN 往返。历史只对相邻结果去重，无法过滤 A→B→A 抖动。

改进：使用 `stable → pending → confirmed` 状态机。首次候选在界面立即显示“正在确认”，同一候选连续出现两次后再于约 500–750ms 内提交；网络路径事件可以降低确认门槛。国内回退需同时满足海外链连续失败和国内链稳定成功。历史与通知只记录 confirmed。

### P0：250ms 全时 HTTPS 轮询成本过高

应用关闭所有窗口后，连续样本仍约占 5.6%–9.3% CPU、约 82MB 内存。当前每 250ms 创建单请求 URLSession 并请求公网服务，理论上每天可达约 34.5 万次地址请求；“无缓存”不等于必须放弃连接和状态复用。

改进：改为自适应检测。平稳期每 1–2 秒轻探测；`NWPathMonitor`、系统代理变化、唤醒、手动刷新或候选变化后进入 250ms burst 5–10 秒；连续失败时对 Provider 开启 10–30 秒熔断并低频探测恢复。若坚持永久 250ms，应优先接入代理软件本地事件，而不是持续公网 HTTPS。

### P0：最坏响应时间与“毫秒级”不一致

实时探针顺序执行 IPv4 1 秒、IPv6 1 秒、国内回退 2 秒，黑洞网络下地址阶段本身可达约 4 秒。完整刷新还可能等待 ipwho.is 与 ip.guide 各自默认 8 秒，最终由 15 秒硬截止中止。相同候选失败后又会被 5 秒 retryBackoff 抑制。

改进：IPv4/IPv6 并发，先取得可用主地址就发布候选；IPv6 作为后续补全。GeoIP 为每个 Provider 设置 1–2 秒上限，并在主服务 250–300ms 未返回时启动 hedged backup，取首个合法结果并取消其余任务。国内 IPIP 地址响应已经包含城市，应在同一次检测中直接复用，而不是再次请求。

### P1：用户看不到“已经检测到变化”

实时触发调用 `refresh(showLoading: false)`，因此完整 GeoIP 返回前，菜单栏和 Dashboard 继续显示旧城市，用户会认为应用没有反应。

改进：增加 `verifying(previous, candidate)` 状态。地址变化后 100–250ms 内将状态点改为检测中，并显示“正在确认新出口”；GeoIP 完成后再替换国家和城市。这样既不把候选冒充真值，也显著改善感知速度。

### P1：规则分流需要显式业务语义

OneBox 规则模式下，海外服务看到东京，国内服务同时看到上海，两者都是真实出口。现有模型只能保存一个地址，并把国内数据源当作海外失败后的回退，无法表达“代理出口”和“直连出口”并存。

改进：模型增加 `routeMode`（代理、直连、分流）和 `probeSource`。默认主标签在代理健康时显示代理出口；Dashboard 可补充一行“国内直连出口：上海”，或者只在高级信息中展示。VPN 关闭且海外链确认不可用时，主出口切为国内直连。

## UI 与交互建议

- Dashboard：保留一个状态徽章，移除 Hero 内重复的“网络正常”；把“出口类型、国家/城市、主 IP、最后确认时间”组成一个主层级。详情使用自适应 Grid，避免网络组织和 IPv6 被过度截断，并提供完整值 Tooltip。
- History：从“结果列表”升级为“变化列表”，展示 `东京 → 上海`、确认时间与来源；10 秒内的往返抖动折叠为一条“检测到不稳定”，不污染主历史。
- General Settings：把“自动刷新”改名为“定期重新校验资料”，把“实时出口检测”作为独立、始终启用的能力；刷新间隔只在定期校验开启后展示，避免当前语义冲突。
- Menu Bar Settings：保留实时预览；在预览下增加正常、确认中、离线三种状态示例，使用户理解状态符号。
- Network Settings：默认只显示“自动选择最快可用服务”和当前出口类型；Provider 顺序、最后耗时、失败次数与熔断状态放入“高级诊断”。
- 视觉层级：减少连续浅灰卡片，主出口卡使用更清晰的白/背景对比；次要说明文字略增对比。当前 0.5pt separator 与灰底组合在 Increase Contrast 下风险较高。
- Logo：设置页保留缩小图标，但建议移到“隐私/关于”或 Toolbar 标题区域并缩为约 36–40pt，避免通用页顶部单独占一整张卡。

## 无障碍风险

- `RefreshGlyph` 和 Popover 动画没有读取 Reduce Motion；应在减少动态效果时取消无限旋转与 Popover 动画。
- `SectionCard` 在 Reduce Transparency 为真时仍叠加 material background，实际上没有完全消除透明材质。
- 状态变化应通过 VoiceOver announcement 表达“正在确认”和“已切换”，但抖动候选不应反复播报。
- 历史行被暴露为 selectable，但没有明确选择后的行为；若不可操作，应作为静态内容而非可选项。

截图无法证明完整键盘操作、VoiceOver 阅读顺序、不同主题和高对比度行为；这些需要单独的可访问性测试矩阵。

## 推荐实施顺序

1. 单一 `ExitSnapshot` 事务 + 候选确认状态机 + confirmed-only 历史。
2. 自适应探测、Provider 熔断、并发地址发现和 GeoIP hedging。
3. 新增 verifying 状态，先反馈“已检测变化”，再提交城市。
4. 明确代理/直连/分流业务模型。
5. 重整 General Settings、History 和 Dashboard 信息层级。
6. Reduce Motion、Reduce Transparency、Increase Contrast 与 VoiceOver 回归。
